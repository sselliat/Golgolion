# 협업 워크플로 라우터

현재 수행하는 작업에 필요한 문서만 읽는다. 여러 작업을 연속해서 수행할 때도 모든
문서를 미리 읽지 않고 각 작업을 시작하기 직전에 해당 문서를 읽는다.

## 항상 적용할 경계

- 모호한 목표, 에픽, 프로젝트 요청 또는 아키텍처 요청은 구현 작업으로 간주하지
  않는다.
- 짧은 이슈 제목만 보고 명시되지 않은 기술이나 범위를 임의로 선택하지 않는다.
- 상위 이슈를 직접 구현하지 않고 승인된 최하위 이슈 하나만 처리한다.
- 하나의 하위 이슈는 하나의 PR로 처리하고 PR 생성 후 다음 작업을 시작하지 않는다.
- 먼저 묻지 않고 작업 범위를 확장하지 않는다.

## 작업별 문서 선택

| 현재 작업                       | 작업 직전에 읽을 문서                                      |
| ------------------------------- | ----------------------------------------------------------- |
| 이슈 조사, 등록, 분할 또는 계획 | `docs/workflows/issues.md`                                  |
| 승인된 최하위 이슈 구현         | `docs/workflows/implementation.md`                          |
| 코드 작성 또는 수정             | `docs/CODE_CONVENTIONS.md`와 해당 문서가 선택한 세부 문서   |
| 커밋 또는 브랜치 작업           | `docs/workflows/commits.md`                                 |
| PR 생성, 수정, 리뷰 또는 merge  | `docs/workflows/pull-requests.md`                            |

단순한 질문이나 읽기 전용 조사에는 작업 결과를 판단하는 데 실제로 필요한 문서만
읽는다. 관련 없는 코드, Git 또는 PR 규칙을 추가로 읽지 않는다.
