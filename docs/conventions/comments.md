# 주석 작성 규칙

[코드 컨벤션 목차](../CODE_CONVENTIONS.md)에서 이 문서의 적용 대상을 확인한다.

## 기본 원칙

- 주석은 기본적으로 작성하지 않는다.
- 일반적인 제어 흐름, 자료 변환, 프레임워크 사용법 또는 코드가 직접 표현하는 동작을 주석으로 설명하지 않는다.
- 이름과 코드 구조로 의도를 표현할 수 있으면 주석 대신 이름을 개선하거나 함수를 분리한다.
- 코드만으로 파악하기 어려운 복잡한 비즈니스 규칙, 도메인 경계, 외부 시스템 제약 또는 직관적이지 않은 선택의 이유만 주석으로 기록한다.
- 사용자는 불필요하다고 판단한 주석을 삭제할 수 있다.
- Agent는 사용자의 사후 삭제를 전제로 과도한 주석을 작성하지 않는다.
- 구현이 변경되면 관련 주석도 함께 갱신하거나 삭제한다.

```ts
// 계약상 만료 시각과 정확히 같으면 아직 유효한 것으로 처리한다.
return expiresAt >= now;
```

결과를 바꾸는 비직관적인 경계 규칙에는 근거를 설명하되, 코드가 직접 표현하는
비교 동작을 반복해서 설명하지 않는다.

## 언어와 형식

- 설명 주석과 JSDoc 본문은 한글로 작성한다.
- 코드 식별자, API 이름, 상태 코드 및 라이브러리 고유 명칭은 원래 영문을 유지한다.
- 짧은 구현 설명은 `//`를 사용한다.
- 여러 줄의 구현 설명도 각 줄에 `//`를 사용한다.
- 문서화 대상에는 `/** JSDoc */`을 사용한다.
- 장식용 구분선이나 주석 박스를 사용하지 않는다.

## JSDoc

- export라는 이유만으로 JSDoc을 작성하지 않는다.
- 호출자가 반드시 알아야 하는 복잡한 도메인 계약, 단위, 시간대, 범위, 부수 효과 또는 외부 시스템 제약이 있을 때만 작성한다.
- 이름과 타입만으로 역할이 분명한 함수와 컴포넌트에는 JSDoc을 작성하지 않는다.
- TypeScript 타입을 JSDoc의 `@param`이나 `@returns`에 중복해서 작성하지 않는다.
- 사용 중단 예정인 API에는 `@deprecated`와 대체 방법을 기록한다.

```ts
/**
 * 한국 시간 기준으로 체결 내역을 일봉으로 집계한다.
 *
 * 체결이 없는 날짜를 이전 종가로 채우지 않는다.
 */
export function aggregateDailyCandles(trades: readonly CompletedTrade[]): readonly DailyCandle[] {
  // ...
}
```

## 비즈니스 규칙과 외부 제약

다음과 같은 복잡한 경우에만 근거를 설명하는 주석을 작성한다.

- 경계값의 포함 여부가 결과를 바꾸는 도메인 규칙
- 일반적인 시간 처리와 다른 시간대 또는 영업일 요구사항
- 외부 API의 페이지 크기 제한과 데이터 연속성 판정
- 외부 API의 확인된 비정상 동작이나 우회 처리
- 인프라 제약 때문에 직관적으로 더 단순한 구현을 사용하지 않은 경우

- 코드에 이미 표현된 수치를 반복하지 않고 해당 수치나 선택이 필요한 이유를 기록한다.
- 외부 제약에 의존하면 공식 문서나 GitHub 이슈 링크를 함께 기록한다.
- 링크가 사라져도 이해할 수 있도록 짧은 근거를 링크와 함께 작성한다.
- 제품 요구사항 전체를 복사하지 않고 관련 문서 경로를 참조한다.

```ts
// 외부 API의 페이지 크기 제한 때문에 마지막 항목의 연속성을 별도로 검증한다.
// 관련 계약: docs/integrations/provider-api.md
```

## TODO

- `TODO`에는 GitHub 이슈 번호와 구체적인 후속 작업을 기록한다.
- `TODO: 나중에 수정`, `FIXME`, `HACK`처럼 추적할 작업이 불분명한 메모를 남기지 않는다.
- 추적할 가치가 없을 정도로 작은 작업은 현재 변경에서 처리한다.
- 임시 우회가 제거되면 TODO 주석도 함께 삭제한다.
- 사람 이름이나 날짜만으로 TODO 소유권을 표현하지 않는다.

```ts
// TODO(#12): 외부 API 응답 키가 확정되면 임시 중복 키를 교체한다.
```

## 억제와 안전하지 않은 코드의 사유

- `@ts-ignore`와 `@ts-nocheck`는 사용하지 않는다.
- 해결할 수 없는 외부 타입 문제 등에만 `@ts-expect-error`를 사용한다.
- `@ts-expect-error`에는 같은 줄에 한글 사유를 반드시 작성한다.
- 임시 억제라면 GitHub 이슈 번호도 포함한다.
- ESLint 또는 coverage 억제는 파일 전체가 아니라 가능한 가장 좁은 범위에 적용하고 한글 사유를 작성한다.
- 타입 수정, 타입 가드 및 코드 구조 개선을 억제보다 우선한다.
- 불가피한 `as`, non-null 단언 `!` 및 `any`에도 인접 한글 주석으로 이유를 기록한다.

```ts
// @ts-expect-error: #18 외부 라이브러리 타입이 실제 런타임 API를 누락한다.
chart.applyOptions(runtimeOptions);

// eslint-disable-next-line no-console -- 작업 실행 환경에서 수집 실패를 기록한다.
console.error(error);
```

## 주석 처리된 코드

- 실행하지 않을 코드를 주석으로 보관하지 않는다.
- 불필요한 코드는 삭제하고 필요하면 Git 기록에서 확인한다.
- 임시 비교 구현이 꼭 필요하면 별도 테스트나 이름이 명확한 함수로 유지한다.
- 디버깅용 로그, 임시 JSX 및 사용하지 않는 import를 주석으로 남기지 않는다.

## 변경 시 검토

- 코드 변경 시 인접 주석이 여전히 정확하고 필요한지 함께 확인한다.
- 코드와 주석이 충돌하면 주석도 같은 변경에서 수정하거나 삭제한다.
- 중복되거나 일반적인 로직을 설명하는 주석은 제거한다.
- 외부 문서 링크가 핵심 근거라면 링크 유효성을 확인한다.
- 생성된 파일에는 생성 도구가 제공하는 헤더만 유지하고 수동 주석을 추가하지 않는다.
- 라이선스 헤더는 실제 법적 요구사항이나 도구 요구사항이 있을 때만 추가한다.
