# 테스트 작성 규칙

[코드 컨벤션 목차](../CODE_CONVENTIONS.md)에서 이 문서의 적용 대상을 확인한다.

## 테스트 계층

- 단위 테스트는 순수 함수와 도메인 계산을 검증한다.
- 통합 테스트는 fixture를 이용해 수집, 변환 및 저장 흐름을 검증한다.
- E2E 테스트는 사용자가 보는 핵심 화면과 상호작용을 검증한다.
- 같은 동작을 모든 계층에서 중복 검증하지 않는다.
- 가장 낮고 빠른 계층에서 검증할 수 있는 동작은 해당 계층에서 테스트한다.

## 테스트 위치

- 단위 테스트는 대상 파일과 같은 디렉터리에 배치한다.
- 여러 테스트에서 공유하는 fixture는 `tests/fixtures`에 배치한다.
- Playwright E2E 테스트는 `tests/e2e`에 배치한다.
- 한 테스트 파일은 대응하는 하나의 대상 또는 하나의 사용자 흐름에 집중한다.

```text
src/
└─ features/
   └─ market-price/
      └─ lib/
         ├─ calculate-current-price.ts
         └─ calculate-current-price.test.ts
tests/
├─ fixtures/
│  └─ neople/
└─ e2e/
   └─ market-price.spec.ts
```

## 테스트 구조와 이름

- 테스트 케이스명은 한글로 작성한다.
- 테스트 케이스명은 구현 방법이 아니라 조건과 기대 동작을 설명한다.
- Arrange–Act–Assert 또는 Given–When–Then 흐름으로 작성한다.
- 한 테스트는 하나의 핵심 행동만 검증한다.
- 여러 assertion이 하나의 행동 결과를 함께 설명하면 같은 테스트에 둘 수 있다.
- 입력과 기대값만 달라지는 경계 조건은 Vitest `test.for`를 사용해 테이블 테스트로 작성한다.
- 변수, 함수 및 타입 같은 코드 식별자는 기존 영문 명명 규칙을 따른다.

```ts
test.for([
  {
    name: '최솟값과 같은 값',
    value: 10,
    minimum: 10,
    expected: true,
  },
])('$name: 허용 범위에 포함한다', ({ value, minimum, expected }) => {
  expect(isAtLeast({ value, minimum })).toBe(expected);
});
```

## 결정성과 격리

- 테스트 실행 순서에 의존하지 않는다.
- 다른 테스트가 생성한 전역 상태나 데이터에 의존하지 않는다.
- 현재 시간, 타임존, 난수 및 네트워크 응답을 통제한다.
- 날짜 계산 테스트는 명시적인 한국 시간 입력 또는 고정 시각을 사용한다.
- fake timer나 mock clock은 각 테스트 후 실제 상태로 복원한다.
- mock, spy 및 전역 stub도 각 테스트 후 복원한다.
- 테스트에서 임의의 실제 현재 시각을 기대값 계산에 사용하지 않는다.

## fixture와 외부 시스템

- 자동 테스트에서 실제 외부 API를 호출하지 않는다.
- 실제 응답에서 확보한 fixture는 비밀값과 식별 가능한 정보를 제거한다.
- fixture는 테스트 목적에 필요한 최소 필드를 유지하면서 실제 API 계약 형태를 보존한다.
- fixture를 테스트 중 직접 변경하지 않는다.
- 외부 API 계약 검증을 위한 제한된 실제 호출은 일반 자동 테스트와 분리한다.

## mock 사용

- 네트워크, 데이터베이스, 시간 및 파일 시스템 같은 외부 경계를 우선 mock한다.
- 순수 도메인 함수는 mock하지 않고 실제 구현을 사용한다.
- 호출 횟수보다 반환값, 저장 결과 및 상태 변화를 우선 검증한다.
- 모듈 전체 mock보다 명시적인 의존성 주입이나 작은 adapter 대체를 우선한다.
- mock 구현이 실제 계약과 달라지지 않도록 같은 fixture와 계약 타입을 사용한다.
- 테스트 사이에 mock 상태를 공유하지 않는다.
- 특정 HTTP mocking 라이브러리는 이 규칙에서 강제하지 않는다.

## Playwright E2E

- 사용자가 보는 동작과 접근 가능한 이름을 기준으로 테스트한다.
- locator는 `getByRole`, `getByLabel`, `getByText`, `getByTestId` 순으로 우선한다.
- CSS class, XPath 및 DOM 위치 기반 selector는 사용하지 않는다.
- `waitForTimeout` 같은 고정 대기를 사용하지 않는다.
- 자동 대기하는 Playwright web-first assertion을 사용한다.
- 각 테스트는 독립된 브라우저 상태와 제어된 API 응답을 사용한다.
- async Server Component의 세부 렌더링은 억지로 단위 테스트하지 않고 E2E에서 검증한다.

기능별 필수 시나리오와 브라우저 범위는 해당 도메인 문서를 따른다. 시세 기능에는
[시세 도메인 규칙](../domains/market-price.md)을 적용한다.

## 차트 시각 검증과 snapshot

- 일반 컴포넌트의 광범위한 DOM snapshot은 사용하지 않는다.
- 텍스트, 역할, 상태 및 계산 결과는 명시적인 assertion으로 검증한다.
- 차트의 실제 픽셀 렌더링은 차트 영역에 한정한 Playwright screenshot 비교로 검증한다.
- 시각 기준 이미지는 동일한 운영체제, 브라우저 및 폰트 환경에서 생성하고 CI에서도 같은 환경을 사용한다.
- 시각 테스트의 시간과 데이터는 고정한다.
- 기준 이미지 변경은 실제 UI 변경과 함께 사람이 검토한다.
- 시각 테스트는 우선 Chromium 한 환경에서만 실행한다.

## 실패, skip 및 retry

- 실패한 테스트를 삭제하거나 assertion을 약화해 통과시키지 않는다.
- `test.only`를 커밋하지 않는다.
- `skip`과 `todo`는 추적 이슈와 사유가 있을 때만 사용한다.
- flaky 테스트를 무기한 skip하지 않는다.
- CI 재시도는 진단 자료 수집 목적으로 최대 1회만 허용한다.
- 재시도에서만 통과한 테스트도 flaky 실패로 간주하고 원인을 수정한다.
- Playwright 실패 시 trace를 우선 진단 자료로 사용한다.
- 타임아웃을 늘리기 전에 불안정한 대기와 외부 의존성을 먼저 제거한다.

## 커버리지

- 초기 코드가 없는 상태에서 임의의 전역 커버리지 비율을 확정하지 않는다.
- 핵심 도메인 순수 함수는 도메인 문서에 정의된 모든 분기와 경계 조건을 테스트한다.
- 새 동작 또는 버그 수정에는 해당 동작을 검증하거나 기존 결함을 재현하는 테스트를 반드시 추가한다.
- 초기 구현 후 측정한 커버리지 기준선을 낮추지 않는다.
- 커버리지 수치보다 누락된 요구사항과 분기를 우선 검토한다.
- 전역 coverage threshold는 초기 구현의 실제 측정값을 확인한 후 자동 검사 규칙에서 결정한다.
