# 이슈와 계획

이 문서는 이슈를 조사, 등록 또는 분할하거나 구현 전 계획과 승인을 판단할 때
적용한다. 구현, 커밋 또는 PR 작업의 세부 규칙은 포함하지 않는다.

## 필요한 프로젝트 문서

- 프로젝트에서 다음 작업을 고를 때만 `docs/project/CONTEXT.md`와
  `docs/project/TASKS.md`를 읽는다.
- 시세 계산, 수집 또는 데이터 상태가 이슈 범위에 포함될 때만
  `docs/domains/market-price.md`를 읽는다.
- 이슈 등록만 수행할 때는 코드 컨벤션, 커밋 및 PR 문서를 읽지 않는다.

## 계획 요청 판정

다음 조건 중 하나라도 해당하면 구현이 아닌 계획 요청으로 취급한다.

- `kind:goal`, `phase:discovery` 또는 `agent:plan-only` 라벨이 지정되어 있다.
- 명시적인 인수 조건이 없다.
- 중요한 기술적 결정 사항이 정해지지 않았다.
- 하나의 작은 코드 변경이 아니라 달성하려는 결과를 설명하고 있다.

계획 요청에서는 다음 작업을 수행하지 않는다.

- 저장소 파일을 생성, 수정, 이름 변경 또는 삭제하지 않는다.
- 프레임워크를 초기화하거나 의존성을 설치하지 않는다.
- 프로젝트 생성 도구를 실행하지 않는다.
- 커밋, 브랜치 또는 PR을 생성하지 않는다.
- 명시적인 승인 없이 언어, 스타일링 방식, 패키지 관리자, 데이터베이스, 테스트
  프레임워크, 디렉터리 구조 또는 배포 플랫폼을 선택하지 않는다.

먼저 다음 작업을 수행한다.

- 목표와 현재 이해한 내용을 다시 정리한다.
- 가정한 사항과 아직 결정되지 않은 사항을 나열한다.
- 영향도가 높은 질문을 소수의 묶음으로 제시한다.
- 실행 가능한 선택지와 장단점을 제시한다.
- 권장안을 제시하되 승인된 것으로 간주하지 않는다.
- 하나의 워크트리와 하나의 PR로 처리할 수 있는 작은 하위 이슈를 제안한다.
- 작업을 중단하고 명시적인 승인을 기다린다.

## 이슈 크기와 계층

- 여러 개의 독립적으로 검증 가능한 결과를 포함한 작업은 구현 전에 하위 이슈로
  분리한다.
- 상위 이슈는 진행 상황과 공통 요구사항만 추적하며 직접 구현하지 않는다.
- 상위 이슈에는 `ready-for-agent` 라벨을 지정하지 않는다.
- 하나의 하위 이슈는 하나의 PR로 검토할 수 있는 범위여야 한다.
- 각 하위 이슈에는 독립적인 결과물, 포함 범위, 제외 범위, 완료 조건과 검증 방법을
  기록한다.
- 파일 수나 변경 줄 수만으로 이슈를 나누지 않는다.
- 앞선 하위 작업의 결과가 다음 작업의 입력이면 앞선 PR의 리뷰와 merge 후 다음
  이슈를 구체화한다.

## 승인 게이트

다음 조건 중 하나를 충족한 최하위 이슈에만 구현 승인이 있다고 판단한다.

- 이슈에 `ready-for-agent` 라벨이 지정되어 있다.
- 사용자가 정확히 `APPROVED FOR IMPLEMENTATION`이라고 작성한다.

계획 승인은 해당 계획과 관련 없는 선택까지 승인한 것으로 간주하지 않는다.
이슈 등록만 요청받았다면 등록 후 구현을 시작하지 않는다.
