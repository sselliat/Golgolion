# 구현

이 문서는 승인된 최하위 이슈를 구현할 때 적용한다.

## 시작 조건

다음 조건을 모두 충족해야 구현을 시작한다.

- 이슈에 `ready-for-agent` 라벨이 있거나 사용자가 정확히
  `APPROVED FOR IMPLEMENTATION`이라고 작성했다.
- 작업 범위와 인수 조건이 명확하다.
- 관련 기술 결정이 정해져 있다.
- 검증 방법이 명시되어 있다.
- 해결되지 않은 차단 질문이 없다.

조건을 충족하지 않으면 구현하지 않고 `issues.md`의 계획 절차를 따른다.

## 작업 범위

- 한 번에 승인된 최하위 이슈 하나만 구현한다.
- 상위 이슈는 진행 상황 추적용으로 사용하고 직접 구현하지 않는다.
- 이슈의 포함 범위와 완료 조건을 넘어 작업하지 않는다.
- 관련 없는 발견 사항은 현재 구현에 섞지 않고 별도 이슈 후보로 보고한다.
- 하나의 하위 이슈는 하나의 PR로 처리한다.
- PR을 생성한 뒤 작업을 중단하고 사용자의 리뷰와 merge를 기다린다.
- 별도 요청 없이 다음 하위 이슈를 연속해서 구현하지 않는다.

## 문서 선택

- 코드를 작성하거나 수정할 때만 `docs/CODE_CONVENTIONS.md`를 읽고, 그 문서의
  선택표에서 현재 변경에 해당하는 세부 문서만 추가로 읽는다.
- 커밋을 만들기 직전에만 `docs/workflows/commits.md`를 읽는다.
- PR을 만들기 직전에만 `docs/workflows/pull-requests.md`를 읽는다.
- 단순 조사나 문서 변경에는 관련 없는 코드 컨벤션을 읽지 않는다.

## 검증과 완료

- 이슈에 명시된 검증을 변경 위험에 비례해 수행한다.
- 실행한 검증과 실행하지 못한 검증을 구분해 기록한다.
- 인수 조건이 남아 있으면 완료로 간주하지 않는다.
- 구현 중 범위나 핵심 기술 결정을 바꿔야 하면 작업을 멈추고 사용자 승인을 받는다.
